# Thesis template engine

`schema.d.ts` is schema v1. All lengths are millimetres, all font sizes and paragraph spacing are points, and line height is a multiplier. `validation.js` checks bundled definitions at load time. `engine.js` resolves global rules plus section overrides into one document model. The thesis editor, print HTML, searchable PDF and DOCX consume that model. The old AcademicEditor and its exporters remain separate.

### Special pages (Task 8)

Cover, approval, declaration/ethics and similar pages are ordinary template sections with a `blocks` layout; there is no second page list and no per-university component. `specialPages.js` is the only interpreter: `resolveSpecialPage` turns blocks + `thesis.values` metadata into a render tree (final text and style per node), `specialPageHtml`/`specialPageCss` render it (no style attributes, CSP-safe) and `flattenSpecialPage` feeds the current PDF/DOCX writers. Block types: `text` (static, `{{KEY}}` still accepted), `metadata` (`field`, `prefix`, `suffix`, `fallback`; date fields are localized), `spacer` (`heightMm`), `separator` (`widthPercent` = line length in a column, `thicknessPt`, `align`) and `group` (`direction: column|row`, `gapMm`, inherited `style`, children may set `widthPercent` = their share of the row). In a row a separator fills its own box. Row shares may shrink but never grow past the content box (`specialPageRowWidths` gives the same widths to DOCX), so a row never crosses the page margin. Any block may set `marginTopMm/marginBottomMm`. Typography inherits template body → section `overrides.body` → group `style` → block `style`. Margins and numbering use the section's existing `overrides.page`; order uses `order`/array position and optional pages use `status: "optional"`. A section with `blocks` is always its own physical page group, so it takes part in the page model and roman/arabic restarts like any other group, while its content never enters an editable body. Metadata edits recompile the model, so the page updates live; the layout is never copied into the note. Demo A/B/generic covers use metadata blocks; Demo B shows cover → approval (counted, unnumbered, 35 mm top margin) → ethics; Demo C shows cover → declaration → optional approval.

Block layouts must be static (including empty layouts); validation rejects editable/generated modes for special pages. Spacer margins, like group and separator margins, are applied in mm. Ordinary editable sections may still use a static `content` introduction. `image` blocks accept an embedded PNG/JPEG `source`, positive `widthMm`/`heightMm` and optional `align` (left/center/right). They use scoped CSS in the editor/print, the same measured image in the PDF, and an inline image paragraph in DOCX.

`pageLayout.js` converts resolved A4 geometry to CSS pixels at 96 dpi and owns the physical page model. `engine.js` groups sections into page flows: a section with `pageBreakBefore !== false`, a numbering restart or different page chrome starts a new page, and cover sections never share a flow with other sections.

### Pagination (Task 7)

Pagination is presentation, not storage. The note still stores `note.content` plus `thesis.sectionContent` per section id; no page HTML, page count or break position is ever written. Each page group renders one `.thesis-page-flow` holding the group's unchanged `RichTextBody` instances. `thesisPagedCss` turns that flow into a single-column multicol whose `column-height` is `page.heightMm - margins.topMm - margins.bottomMm`, whose `row-gap` is bottom margin + desk gap + top margin and which uses `column-wrap: wrap; column-fill: auto`. The browser's fragmentation engine therefore breaks text by line (orphans/widows 2), keeps headings with `keepWithNext` on the next page (`break-after: avoid`), moves a table/figure that fits a page as a whole and splits longer tables by row, continues `ol` numbering, applies heading `pageBreakBefore` as a column break, and lets oversized monolithic content overflow instead of looping. Typing, deleting, font/template/window changes reflow natively; the caret, selection, focus, undo stack and DOM identity are untouched because nothing is split or re-inserted.

A ResizeObserver reads only the unscaled flow height; `pageCountFromFlowHeight` maps it to N pages (N content boxes + N−1 row gaps, rounded, clamped to `THESIS_MAX_PAGES`). `buildThesisPageModel(groups, counts)` returns one entry per physical sheet with its label (`numbering.enabled/format/startAt/restart`: none, roman or arabic), `numbering.position` (top/bottom) and `align` (left/center/right), and header/footer first-page omission. The editor draws white `.thesis-sheet` elements and their chrome from that model behind the transparent flow. Zoom is a transform on the whole stack, so every zoom level has the same page count and breaks. Print and DOCX use the page groups; the PDF (Task 9) is drawn from this page layout. Engines without `column-wrap` keep the Task 6 continuous surface.

Thesis notes use `noteType: "thesis"`. The document is the normal TxtNote note: `note.title` and `note.content` hold the title and main rich-text HTML, while `note.researchData.thesis` holds the template reference, student metadata, optional section choices and other editable section HTML. `document.js` creates and updates this state without writing into a template. Sections are template data. `compileThesisDocument` walks `orderedThesisSections(template)` (optional numeric `order`, else array position), drops `disabled` sections and `optional` ones not listed in `thesis.enabledSections`, and the editor renders whatever comes out; it has no per-section or per-university branch. Each section has a `mode`:

- `editable` — the user writes it. `mainContent` is `note.content`; every other editable section is `thesis.sectionContent[section.id]`. Identity is the stable `id`, never the position, so reordering or switching templates cannot move text between sections. Bundled templates use the same id for the same section type.
- `static` — `content` / `blocks` belong to the template and are read-only.
- `generated` — built from the document (TOC, list of figures and list of tables via generatedIndex.js). Stored user HTML is ignored.

Section titles come from the template (`title`, `toc.heading`); `showTitle` overrides whether the title is printed. Templates without `mode` keep working: `editable: true` → editable, TOC/list types → generated, `editable: false` or content/blocks → static, otherwise editable. `mode` and `editable` must agree when both are set. Existing SQLite, backup, undo and sync paths persist the note. A missing or invalid template resolves to the explicitly generic draft and displays a warning.

## Add a university template

1. Obtain a current official guide. Record its URL, document name, revision date and verification date in `source`.
2. Add a data module in `templates/`, exporting a `ThesisTemplate`. New versions need **new IDs**; keep old modules loadable for existing notes.
3. Add one metadata descriptor and dynamic `load` import in `registry.js`. Selection and the editor read that descriptor; no editor branch is needed.
4. Run `node --test src/lib/thesisEngine.test.js` from `frontend/` and `npm run build` from the repository root. Add a test fixture for any newly encountered rule.

### Generated from an official DOCX (Task 13)

Most universities publish a Word template; the measured pipeline turns it into a draft template without hand-writing values (repository root):

1. `python3 scripts/extract-docx-spec.py <official.docx>` → `output/docx-spec/<name>.spec.json`: sections, margins, numbering, resolved styles, real paragraph usage, and `frontPages` — the opening pages (up to the first front-matter title) paragraph by paragraph with alignment, size, weight, spacing, embedded images (PNG/JPEG as data URLs with mm sizes), tables, and the template's own instruction text boxes (kept as notes, never as layout).
2. `python3 scripts/docx-spec-to-template.py <spec> --university-id … --university-name … [--institute-id … --degree …]` → `output/template-drafts/<id>.draft.json` = `{ template, unknown[], inferred[], evidence{}, valid }`. Front pages become `layoutMode: "editable"` sections (outer/inner cover by position; approval, declaration, dedication by their titles): blank Word lines become spacers of the measured line height, text keeps its own alignment/size/weight/line spacing, tables become row groups, and lines that stand for a value (“TEZ BAŞLIĞI”, “Öğrencinin Adı SOYADI”, a name line under “Danışman”, “ANABİLİM DALI”, “Ay Yıl”, “Şehir, Yıl”, project-support lines) become metadata blocks with the original text as fallback — each such guess is listed in `inferred`. Everything the DOCX does not establish is listed in `unknown`; nothing is invented.
3. `node scripts/validate-template-draft.mjs <draft>` runs the engine validator; `node scripts/install-template-draft.mjs <draft> [--status generic|official]` writes `templates/generated/<id>.js` and rebuilds `templates/generated/index.js`, which `registry.js` appends to the registry. Drafts install as `generic` ("(taslak)" in the selector); `official` is reserved for templates whose real export has been measured against the source (AGENTS.md completion gate).

Open the result in the browser fixture with `tests/thesis-editable.html?template=<id>`.

**Guide text (Task 14).** `python3 scripts/extract-guide-rules.py <kılavuz.pdf|docx> [--summary]` reads the official guide sentence by sentence and records every measurable statement as an EXPLICIT rule with its sentence and page/paragraph — margins per side, font, point sizes, line spacing, paragraph indent/spacing, caption position and labels, page-number position, heading case/weight, footnotes, bibliography indent — scoped by the clause it appears in (body, caption, heading, footnote, abstract, cover, …); a rule the guide states twice with different values is a CONFLICT and is never applied. `python3 scripts/merge-guide-rules.py <draft> <rules>` fills a draft's UNKNOWN fields from EXPLICIT rules (a measured DOCX value is kept; a differing guide value is recorded in `conflicts`, not averaged), and can build the `tables`/`figures` rules that bare templates lack (position from the guide, size from the guide or body — the latter flagged INFERRED). `scripts/batch-template-drafts.py` then `scripts/batch-guide-merge.py` run both passes over `Butun-Sablonlar` and write `output/template-drafts/batch-report.md`. Extraction is pattern-based and reviewed by a person before a template is installed; the sentences are there to be checked.

The three `demo-*` entries are invented test fixtures. No university policy is implied.

### Export (Task 9)

Export is derived output; nothing (page HTML, page counts, breaks) is written to the note, and it always reads the current model, so fresh metadata is exported immediately.

- **PDF** (`layoutPdf.js`) does not paginate. It reads the editor's already paginated page stacks — every word, list marker (`::marker`), heading number (`data-thesis-number`), border, image and sheet chrome — and draws each at the same position on the same sheet as searchable text (Tinos for Times New Roman, which is metric-compatible; Helvetica/Courier for Latin-1 words in Arial/Courier templates, Tinos otherwise — so a Turkish word in an Arial template is drawn in a serif face; embedding a metric-compatible sans needs a licensing decision, see Current boundary). Page count, breaks, numbering, restarts, special pages and margins are therefore the editor's own. Positions are divided by the stack's exact transform scale (not the rounded `offsetWidth`), so zoom never changes the PDF and margins land on the millimetre. Engines without the paged layout fall back to `buildThesisPdf(model)` in `export.js` (its own shaper, as before).
- **DOCX** (buildThesisDocx) keeps Word semantics: one Word section per thesis section (nextPage for a new page group, continuous inside one), exact A4, section numbering/restarts and header/footer PAGE fields. Real editor paragraphs become Word paragraphs with first-line indent, before/after spacing, line height and explicit alignment. Shift+Enter becomes an inner Word break. Legacy loose lines keep their former no-spacing export. Heading styles, including Heading4 with outline level 3, come from the resolved rules. Tables/images remain real Word objects, captions become separate paragraphs above/below them, and generated indexes are visible resolved rows with Word tab leaders and the editor's measured page labels. Word lays out its own pages: resolved labels are a snapshot of TxtNote pagination and are not Word TOC fields. Inline formatting, lists, citations, bibliography, footnotes and special page blocks use the existing exporters.

## Generic extensions (Task 10A)

The thesis editor opts into real paragraph editing; the legacy AcademicEditor remains separate. Enter uses the browser's paragraph command and undo stack; Shift+Enter inserts an inner line break (Chromium may represent it as a newline under pre-wrap). Body TextStyle remains backward compatible. An optional typography.paragraph and section.overrides.paragraph apply the same unit-bearing properties: firstLineIndentMm, spaceBeforePt, spaceAfterPt, lineHeight and align. New paragraphs inherit paragraph alignment/style without promoting inline selection formatting to a paragraph style. Existing loose text/newlines are not rewritten on open. thesisSourceHtml strips presentation stamps using deterministic, idempotent string normalization; saves defensively strip them again.

Headings use the configured level map, with H1–H4 in the generic demo defaults. collectIndexSources produces one ordered source stream across active sections, with semantic heading counters and caption counters. Per-chapter captions use the H1 counter and its sequence, never numbers parsed from the heading title or its formatted label. Before the first numbered H1 the chapter counter is 0. Global counters use numbering.scope: document; chapter counters use scope: chapter. Existing caption keys (label, position, style, numbering, spacingBeforePt/spacingAfterPt) remain the API. captionAlignment adds left/center/right/justify/auto. Auto measures a single line as centered, multiple lines as justified; DOCX receives this measured alignment from the editor. Figure captions are editable while the image remains locked.

A generated section can declare generatedIndex: { kind: toc | figures | tables, title, levels, maxDepth, includePageNumbers, leader: dots | none, pageNumberAlignment, indentMm, style }. Older tableOfContents/listOfFigures/listOfTables section types resolve to the same rule automatically. Other generated section types retain their title/empty placeholder. Indexes are selectable/copyable, have no RichTextBody, and never enter source state.

renderedIndexPages reads anchor text rects from the existing browser-fragmented page flow, divides by the exact stack transform and resolves the group/page against buildThesisPageModel. It returns both the visible label (including roman numbering or blank unnumbered pages) and the physical page. resolveGeneratedIndexes creates a view model only. The editor measures/render-updates until stable, with a six-update cap and a visible warning retaining the last measured result if convergence fails. Source edits, image/font loads, flow resizing and zoom trigger measurement. Generated rows, anchors and calculated page numbers are never stored in note.content or thesis state. No pagination engine is added.

Optional pages still use status: optional with enabledSections. visibleWhen accepts exactly one declarative equals/notEquals/in operator and a metadata field; degreeType also resolves the document degree. No expressions or JavaScript are accepted. validation is a map of metadata/section fields to { minItems, separator?, severity?, message? }. The compiler returns semantic errors/warnings and the editor displays their count/message. These advisory rules never block saving or exporting.

## Current boundary

PDF continues to read the actual paginated editor DOM. The existing Arial/Turkish glyph fallback remains unchanged. Engines without column-wrap use the existing continuous/fallback writer; they cannot resolve real generated index page labels, which remain blank rather than estimated. DOCX uses the current TxtNote page-label snapshot; Word may reflow differently, and modifying the Word file does not update those resolved index labels automatically.

Footnotes: see Task 10A.1 below. The legacy academic “Tez” skeleton is still present and separate.

## Page-bottom footnotes (Task 10A.1)

A note is drawn at the bottom of the physical page on which its reference is rendered. `footnotes.js` is the only interpreter; it has no university knowledge.

- **Template data.** `typography.footnotes` (and `section.overrides.footnotes`) accept the usual TextStyle keys (fontFamily, fontSizePt, fontWeight, italic, lineHeight, align, characterSpacingPt, spaceBeforePt/spaceAfterPt between notes, indents) plus `placement: pageBottom | sectionEnd`, `maxAreaPercent` (10–90, default 50) and `separator: { enabled, widthPercent, thicknessPt, spaceBeforePt, spaceAfterPt }`. Defaults: body font, 9 pt, line height 1.2, left, a 33 % × 0.5 pt rule with 6 pt/3 pt spacing. A guide that requires e.g. Times New Roman 10 pt sets that in its template; DOCX footnotes use the same rule.
- **Ownership.** The page of a note is the page of its `sup.academic-footnote` rect in the existing fragmented flow (unscaled, divided by the stack transform), never a guess from numbers. Numbering stays the existing per-body `data-fn-index`; order is document order.
- **Body capacity, no second paginator.** The browser's multicol still breaks every page. For a page with notes of height H the body must end at `contentHeight − H`. The block crossing that limit gets one presentation attribute: a splittable block gets `data-thesis-fn-stamp="reserve"` (a `box-decoration-break: clone` bottom padding via typed `attr()`, so its first fragment stops above the notes and its lines continue on the next page; a negative margin cancels the padding after its last fragment); a monolithic block (heading with keep-with-next, figure, table row, a one-line paragraph) gets `data-thesis-fn-stamp="break"`. The notes themselves are an absolutely positioned, non-editable area on the sheet layer (`.thesis-footnote-layer`), measured by a hidden twin with identical CSS. Engines without `column-wrap`, clone padding or typed `attr()` keep the section-end list.
- **Word rule and stabilization.** Every reference on a page gets at least the start of its note. If a reference line plus its note does not fit, the body ends above that line and the reference moves to the next page with its note. Pages are processed in order (a page only depends on earlier ones); a page whose references, note texts, carried continuation and stamp geometry are unchanged keeps its stamp without relayout, a page whose text merely shifted moves its stamp to the new crossing block. Stamps are in-memory records, never stored. The editor's generated-index loop now lays out notes first and then reads index pages, under one signature and the same six-update cap (warning "Dizin/dipnot sayfalaması kararlı hale gelmedi"). A 24 ms frame budget lets long documents re-lay later pages progressively while typing stays responsive; an unfinished pass is not an iteration.
- **Long notes.** The note area never exceeds `maxAreaPercent` of the page body. A note that does not fit is split at a word boundary (leaving room for the first word of each later note on that page); the remainder continues at the top of the next page's area, unlabelled, before that page's own notes. A continuation longer than the rest of the group adds continuation-only pages after the body (1 px spacers in the flow). Nothing is clipped or overlaps and the loop is bounded.
- **Persistence.** `thesisSourceHtml` strips `data-thesis-fn-*`; note areas, heights, page assignments and spacers are view state. The note stores only the existing reference markup (`data-fn-id`, `data-fn-text`).
- **PDF/DOCX.** The layout PDF reads the same DOM, so notes, separator and page count match the editor. DOCX keeps real Word footnotes (`FootnoteReferenceRun`); Word places them itself.
- **Limits.** Loose legacy text outside paragraphs is one block; if it crosses a limit, its reservation repeats on every page it spans. A single paragraph longer than a page likewise repeats a reservation on its later fragments. A monolithic block taller than the space above the notes at the very top of a page cannot move and is left in place. Print (`buildThesisPrintHtml`) is unchanged and does not render notes.

## Editable layouts (Task 11)

A blocks section may declare `layoutMode: "editable"` (with `mode: "editable"`). Its blocks are then a **seed**, not a fixed page: the first time the section has no stored text, `compileThesisDocument` resolves the blocks (`resolveSpecialPage` with `keepOptional`) and writes them as ordinary editor HTML (`specialPageSeedHtml`); from the first keystroke on, the user's HTML is stored in `thesis.sectionContent[id]` like any editable section, and the static block renderer/exporter is not used for it (`specialPage: false`, `layout: null`). The section is still its own physical page (`groupThesisSections`), keeps its `overrides.page/body`, and prints no section heading unless `showTitle: true`. The toolbar offers "Şablona sıfırla" for a seeded section with stored text: it clears the stored HTML, so the next compile reseeds from the template.

Seed vocabulary is the editor's own, CSP-safe (no style attributes), and read back by the DOCX writer through `parseAcademicHtml`:

- text → `<p class="fmt-align-…">` with `<strong>/<em>/<u>` and `<span class="fmt-pt-N">` for sizes in the format menu (`FORMAT_POINT_VALUES`), `data-pt="N"` (pt) otherwise; `textTransform` is baked into the text; block margins become `data-space-before/after` (pt). `fmt-align-justify` is now a menu option.
- metadata → a **field chip** `<span class="thesis-field" data-field="KEY" data-fallback data-prefix data-suffix data-transform contenteditable="false">` showing the current value (or the fallback). `refreshThesisFieldHtml` updates chip text on every compile, so metadata edits stay live until the user deletes the chip.
- `visibleWhen: { anyFilled }` → the block keeps `data-thesis-optional="A,B"`; `refreshThesisFieldHtml` adds `data-thesis-hidden="true"` while none is filled (CSS `display:none`, skipped by the parsers). `data-thesis-hidden` is presentation and is stripped by `thesisSourceHtml`.
- spacer → `<p class="thesis-gap" data-gap="mm" contenteditable="false">`; separator → `<hr class="thesis-rule fmt-align-…" data-length="%" data-thickness="pt">`; image → `<figure class="academic-figure fmt-align-…"><img width height>` (px at 96 dpi); row group → `<table class="thesis-layout-row">` with `td[data-width="%"]`; column groups flatten.
- Numeric data attributes are drawn with unit-form `attr()` (`attr(data-gap mm)`, `attr(data-pt pt)`, `attr(data-length %)`), the same syntax the footnote feature test relies on. Thesis CSS (`thesisSectionCss`) also styles `.fmt-pt-N` and `.fmt-align-justify` inside `.thesis-body`; `index.css` exempts `table.thesis-layout-row` from the editor's forced cell borders.
- Block model (`parseAcademicHtml`, DOM and regex paths): runs carry `sizePt` (from `fmt-pt-N`/`data-pt`), paragraphs `spaceBeforePt/spaceAfterPt/sizePt`, new blocks `gap {heightMm}` and `rule {lengthPercent, thicknessPt, align}`, tables `className` and cells `widthPercent` + nested `blocks`; hidden blocks are dropped. `export.js` writes gaps as exact-height paragraphs (`spacerParagraph`), rules as bottom-bordered paragraphs (`ruleParagraph`), layout rows as borderless fixed tables (`layoutRowDocx`), run sizes as `w:sz`. The layout PDF reads the DOM, so it follows automatically.

Fixture: `templates/demo-d.js` (DEMO Üniversite D: editable cover with an optional co-advisor line, image, and a jury page with a three-column signature row); unit tests `lib/thesisEditableLayout.test.js`; browser test `tests/thesis-editable-layout.e2e.mjs` on `tests/thesis-editable.html` (seed geometry, live chips, editing, reset, DOCX). Limits: a seeded page is text once edited — moving a block back to the template's millimetre geometry is only possible through "Şablona sıfırla"; `standalone: false` is not supported for editable layouts; row cells hold paragraphs, not nested rows.

## Template compliance audit (Task 12)

`compliance.js` compares the compiled model with the template's resolved rules and lists departures; the editor's **Denetim** button shows the counts and opens a panel whose findings jump to their section. Pure data: `checkThesisCompliance(model, { groups, pageCounts })` → `{ findings, errors, warnings, infos }`, each finding `{ severity, code, sectionId, sectionTitle, message, expected, actual, source }` with `source` naming the template path the expectation comes from. Nothing is stored; the audit is recomputed from the model and the measured page counts.

Checks (all read from the section's `rules`, never from a university name): required metadata missing on a page (`metadata.missing`, error); seeded layouts edited away from the fresh seed, paragraph by paragraph (`layout.align/size/weight` warnings, `layout.fieldRemoved` error for a required field, `layout.lineRemoved`/`layout.extraLines` info) — the compiler keeps `section.seedHtml` next to the stored text for this; body paragraphs whose explicit marks differ from `typography.body` (`paragraph.align`, `paragraph.size`), pseudo headings made of enlarged text (`heading.pseudo`), skipped heading levels (`heading.skip`), figures/tables without a caption (`figure.caption`, `table.caption`), coloured text (`text.color`, info: no template rule); empty required editable sections (`section.empty`, main body excepted); standalone pages that overflow one sheet (`page.overflow`, error, from `pageCounts`); the template's own `validation` rules (`validation.*`). Severity: error = a template requirement is broken; warning = formatting departs from the template; info = no rule decides it. Errors sort first.

Boundary: the audit sees what the model carries — marks, structure, metadata, page counts — not rendered geometry; millimetre validation of exports stays with the measurement scripts. Tests: `lib/thesisCompliance.test.js`; browser: `tests/thesis-compliance.e2e.mjs`.

## PASS gate (Task 15)

A template is not done because its draft validates (AGENTS.md §13–15). `tests/thesis-export-gate.e2e.mjs <templateId> <outDir>` opens the template in the real editor with a deterministic multi-page document (headings, paragraphs, a captioned figure and table, metadata) and downloads the DOCX and the layout PDF. `python3 scripts/pass-gate.py <templateId> [--guide rules.json]` then measures them: PDF with PyMuPDF (page size; left/right margins from the x0/x1 modes of full justified lines, ≤ 0.5 mm; top from the first glyph box, ≤ 2 mm; bottom gap of the fullest page within one line of the margin; baseline pitch against `lineHeight × size × singleLineEm`, ≤ 0.3 pt; dominant font and size; page-number side and centre, ≤ 0.5 mm; Roman→Arabic sequence; text drawn twice at one spot), DOCX with `extract-docx-spec.py` (section margins and page size, ≤ 0.5 mm; real body font/size/line spacing/alignment; Roman/decimal section formats; PAGE field alignment), and, independently of the draft, the guide's EXPLICIT rules against the installed values. Each check records expected, source, measured, tolerance and PASS/FAIL/LIMIT; LIMIT is a documented engine limit (the PDF embeds Tinos for Times New Roman) and blocks an overall PASS. Report: `output/pass-gate/<id>/gate-report.md`. AKÜ FBE 2025 (generated draft): 36 PASS, 1 LIMIT (font).

## First official template: MCBÜ (Task 10B)

`templates/mcbu.js` is Manisa Celal Bayar Üniversitesi, Lisansüstü Eğitim Enstitüsü, built only from the institute's examples/rules PDF (`ShareFileGallery-GTSM221020251445.pdf`, recorded in `source`). It is data: one module exports a master's and a doctoral variant (registry ids `mcbu-lee-master-tr-v1`, `mcbu-lee-phd-tr-v1`) that differ in their degree lines and the doctorate-only ÖZGEÇMİŞ (`visibleWhen degreeType = phd`). Every page — İç Kapak, Taahhütname, ÖZET/ABSTRACT headers and footers, the Önsöz signature — uses the generic block renderer; nothing in the engine or editor names the university. Choices where the PDF is silent or contradicts itself are commented in the template.

It needed these generic, opt-in extensions (existing templates are unaffected):

- `section.standalone: false` on a blocks section: the block layout flows with its neighbours under the normal `pageBreakBefore` rule, so fixed lines can sit above/below an editable section on one page (ÖZET header → editable abstract → keywords).
- `section.tocEntry`: `"title"` lists the section title as an unnumbered level-1 TOC row with its real page label (front matter in Roman numerals, generated and special sections included); `"none"` keeps the section and its headings out of the TOC. The anchor of a generated/special section is its flow section element.
- `generatedIndex.pageHeading` / `pageHeadingStyle` (a "Sayfa" column heading) and `matchHeadingTransform` (TOC rows read like their rendered headings, e.g. uppercase chapters).
- `tables.cellStyle`: cell typography (single spacing, centered names/values) in editor, PDF and DOCX; the type size stays inherited.
- `captionNumberingChoices`: document-wide numbering methods the author picks in the thesis panel (`thesis.captionNumbering`); applied to figures and tables together.
- Registry `displayName` (selection label) and official sources identified by `documentName` when there is no public URL.

Fixes found on the way: template HTML (section titles, special pages, indexes) is rendered through a memoized wrapper so React does not re-inject it (and drop the TOC anchors) on unrelated re-renders; measured caption auto alignment now outranks the base caption rule; thesis figure captions are document black.

### MCBÜ source limits and open specifications

The supplied 12-page `ShareFileGallery-GTSM221020251445.pdf` contains examples on pages 1–10 and general rules on pages 11–12. The template and both degree variants are already registered in the existing creation and editor selectors. The examples establish the inner cover, declaration, abstracts and preliminary indexes; they do not establish every submission requirement. Treat `status: "official"` as source provenance, not a claim that every rule or export has passed compliance.

- **Guide revision:** `2024-02-22` is the PDF's creation/modification date. The existing `source.revisionDate` records that date, but the document does not identify it as a policy revision. A confirmed guide revision and current official download URL remain unavailable from the supplied file; the filename's date is not proof of either.
- **Abstract spacing:** page 4 asks for single spacing with a blank line between paragraphs, then asks for 1.5 spacing and a 12.5 mm first-line indent. The implementation uses the latter paragraph rule. Institute clarification is needed to settle the contradiction.
- **Preface spacing:** page 6 asks for single spacing and blank lines between paragraphs, while page 11 includes preface/thanks in the general 1.5-spacing rule. The implementation follows the dedicated example. This remains a source conflict.
- **Bibliography spacing:** page 11 exempts references from the general 1.5-spacing rule without supplying a replacement. The current single-spacing setting is an implementation choice requiring confirmation. The guide lets the author choose one consistent citation method; it does not mandate APA or Chicago.
- **Page-number placement:** Roman preliminary numbering and Arabic body numbering are explicit; exact position/alignment are not. Bottom-center placement follows the guide's examples and is not an independently stated requirement.

## MCBÜ final polish (Task 10B.1)

Four generic, opt-in additions; templates that do not use them are unchanged.

- `typography.lineSpacing: { mode: "word", singleLineEm }`: a stored lineHeight is Word's "n lines". Editor/print CSS (and so the layout PDF) draw n × `singleLineEm` × font size; DOCX writes Word's own auto spacing (240 × n) instead of the "at least" pitch. MCBÜ uses Times New Roman's 1.15 em, measured in the official PDF (single 13.8 pt, 1,5 satır 20.7 pt at 12 pt); its empty-line gaps use the same Word line. Default/omitted: the old CSS multiplier.
- Per-chapter caption numbers before the first numbered chapter (an unnumbered introduction) leave out the `{chapter}` part (`Şekil 1`, then `Şekil 1.1` in chapter 1) instead of `0.1` (`formatCaptionNumber`).
- Special page blocks accept `visibleWhen: { anyFilled: [fields] }`; a block or group is left out when none of those metadata values is filled (MCBÜ's optional İkinci Danışman / Co-Supervisor line with its empty line).
